## 企劃概要

《森羅物語：樂牧》是一款以「養動物」為主題的 Minecraft 基岩版附加包，把原版「餵兩下就繁殖」的牲畜，變成需要照顧、也會以品質回報你的牧場。

它以《森羅物語：廚房》v1.6.6 為宿主，透過廚房公開的擴充 API 註冊食譜與手冊內容，不修改廚房本體。

| 項目 | 內容 |
| --- | --- |
| 中文名 | 森羅物語：樂牧 |
| 英文名 | Kaleidoscope Ranching |
| 命名空間 | `kaleidoscope_ranching` |
| 平台 | Minecraft 基岩版，最低引擎 1.26.1（與廚房 v1.6.6 相同） |
| 性質 | 原創、非官方的系列擴充；不是 Java 模組的移植 |
| 首版目標 | 1.0.0：照顧系統、公母與繁殖、10 種自有動物（6 種取代原版、4 種新增）、屠體與屠宰、乳蛋加工鏈、約 20 道料理、對外 API、光影支援 |
| 文件狀態 | 正式版，2026-11-15 定稿，2026-11-16 修訂；所有設計決策見文末「已定案決策」 |

三個設計支柱：

- **照顧有回報**：飼料、飲水、刷毛、放牧決定動物的好感度，好感度決定產物品質。
- **產物能入菜**：乳、蛋、肉全部能進廚房的炒鍋、湯鍋、蒸籠、砧板與石磨。
- **不拖慢伺服器**：沿用廚房移植版的原則，只靠互動事件與結算，不做全域輪詢。

## 系列定位

樂牧負責系列裡「食材從哪裡來」的畜牧端，加工與烹飪仍交給既有模組，避免功能重疊。

| 模組 | 與樂牧的關係 | 整合方式 |
| --- | --- | --- |
| 廚房（Cookery） | 宿主，必要依賴。樂牧的乳、蛋、肉進入其炒鍋、湯鍋、蒸籠、砧板、茶壺、石磨 | `register_recipe`、`register_wok_meat`、手冊擴充 API、菜刀標籤 |
| 煙火（Grilling） | 可選。鴨、鵝、氂牛肉可上烤架 | 偵測到才註冊，缺席時不報錯 |
| 漁歌（Fishing Voyage） | 可選。雜魚、魚骨可做成家禽飼料 | 飼料配方的替代材料 |
| 酒館（Tavern）與世界名酒 | 可選。乳製品可作調飲材料 | 1.0.0 不做，留待後續版本 |

相容原則依廚房的《腳本架構》文件：樂牧擁有自己的識別碼與資料，只向宿主註冊；移除樂牧時，廚房不需要任何修改。

## 核心玩法循環

玩家每天重複「飼養、照料、收成、加工、料理」五步，料理剩下的廚餘與作物再回到飼料，形成閉環。

```mermaid
flowchart LR
    A["飼養<br/>飼槽放飼料，水槽補水"] --> B["照料<br/>撫摸與刷毛，好感度上升"]
    B --> C["收成<br/>依好感度產出三級乳蛋"]
    C --> D["加工<br/>奶油、乳酪、鹹蛋、皮蛋"]
    D --> E["料理<br/>進廚房做成約 20 道菜"]
    E -- "廚餘與作物製成飼料" --> A
```

一天的照顧約需 2 到 3 分鐘：補飼料、補水、逐隻撫摸或刷毛。回報在隨後幾天累積，好感度越高，收成的品質與數量越好。

### 公母與繁殖

- 每隻樂牧動物在出生或生成時決定性別，公母各半。
- 成體的性別可從外觀分辨。幼體外觀不分公母，要用牧場記事本查看，或等牠長大。
- 只有母畜能擠奶、母禽能產蛋。公的屠體分切量較多，羊毛與氂牛毛公母皆產。
- 繁殖需要同種一公一母，雙方當日需求都滿足。兩隻同性餵食後不會繁殖。
- 牛、羊、山羊、豬、兔、水牛、氂牛：母畜配種後懷孕 3 個遊戲日，然後生下幼體；懷孕期間不能再配種。
- 雞、鴨、鵝：不直接生出幼體，改由受精蛋孵化，孵化需 2 個遊戲日，規則見下一節。
- 一隻公的可以配同一飼槽範圍內的多隻母的，建議比例為一公配八母以內。
- 用奶瓶餵幼體可加速成長並提升好感度。

### 受精蛋與未受精蛋

| 種類 | 取得條件 | 用途 |
| --- | --- | --- |
| 未受精蛋 | 母禽每日產出；範圍內沒有同種公禽時全部為此類 | 食用、入菜、醃製；不能孵化 |
| 受精蛋 | 飼槽範圍內有同種公禽時，依母禽好感度的機率產出 | 放進巢箱孵化成幼禽；也可食用 |

- 雞的未受精蛋就是原版雞蛋，廚房既有的雞蛋食譜全部照常可用；受精雞蛋是樂牧的獨立物品。
- 鴨蛋與鵝蛋同樣各分受精與未受精兩種。
- 投擲原版雞蛋不再孵出小雞，幼禽只能由受精蛋在巢箱孵化取得。
- 受精蛋不分品質；孵出的幼禽性別隨機，並繼承親代部分好感度。

### 每日需求

- **飼料**：附近飼槽有對應飼料即滿足。1.0.0 的飼料分乾草、混合飼料、精飼料三級；新作物苜蓿是混合飼料的主料，豬可吃廚餘與乳清。
- **飲水**：附近水槽有水即滿足。
- **照料**：當日被撫摸或刷毛一次即滿足。
- **清潔**：動物每日產生糞便，畜欄內糞便堆積過多即不滿足，需用糞叉清理。此項可在設定中關閉。

### 好感度與品質

- 好感度分 0 到 5 心。四項需求全滿足的一天上升，連續缺飼料或受傷則下降。
- 動物零食與鹽磚可額外提升好感度：零食是每種動物各自愛吃的食物，鹽磚放在畜欄內對範圍內動物生效。
- 產物品質分普通、優良、極品三級，由好感度與當日飼料等級決定，適用於奶與未受精蛋。
- 高好感動物每日產量較高，繁殖冷卻較短；幼體繼承親代平均好感度的一部分作為起始值。
- 用牧場記事本對動物互動，可查看名字、性別、好感度、懷孕狀態與當日需求；掛上耳標的動物會列在記事本的名冊中，且不會自然消失。

### 實作原則

- 十種動物都是樂牧自有的實體，各有公、母、幼體外觀，也有自己的 AI，會主動走向飼槽與水槽。
- 外觀與原版造型對齊：臉部正面的小方塊眼睛、原版的腿長與身形比例，不走大眼睛的 Q 版路線。公的體型比母的大一些（約 1.1 至 1.15 倍）。
- 幼體是獨立的模型，頭大、身短、腿細，不是把成體直接縮小；幼體的毛色也和成體不同，例如小雞是黃色毛球、小牛是淺棕色。
- 原版的牛、羊、山羊、豬、雞、兔在生成或載入時，由腳本事件轉換成樂牧版本，保留位置、名字、幼體狀態與羊毛顏色，性別隨機指定。既有存檔的動物也會自動轉換。
- 性別寫在實體屬性上以切換外觀；好感度、懷孕狀態與上次結算日存在實體的動態屬性。
- 需求採「延遲結算」：只在玩家互動或飼槽結算時，依經過的天數一次算完，不逐刻掃描全世界。
- 沒被照顧的動物不會死亡，只是停在普通品質與低產量。

## 產物與加工鏈

產物分乳、蛋、肉、毛羽、副產物五線；前三線的終點是廚房的料理，副產物則回到牧場與農田。

| 產線 | 原料 | 樂牧內加工 | 去向 |
| --- | --- | --- | --- |
| 乳 | 牛奶、山羊奶、水牛奶、氂牛奶（瓶裝，可堆疊，分三級） | 奶油、鮮奶油、酥油、優格、新鮮乳酪、熟成乳酪 | 廚房：奶油燉菜、乳酪焗烤、奶茶、酥油茶 |
| 蛋 | 雞蛋、鴨蛋、鵝蛋（各分受精與未受精） | 鹹鴨蛋、皮蛋 | 廚房：皮蛋瘦肉粥、鹹蛋黃炒菜、蒸蛋 |
| 肉 | 十種動物的屠體 | 屠宰掛架分切成生肉、部位肉、大骨 | 廚房：老鴨湯、紅燒五花肉、燉牛腩、大骨高湯；煙火：烤鴨、燒鵝 |
| 毛羽 | 羊毛、氂牛毛、羽毛、羽絨、皮 | 鞣皮架：皮 → 皮革 | 原版配方與裝飾；1.1 前，氂牛毛、羽絨可先合成羊毛 |
| 副產物 | 糞便、豬板油、乳清、豬鬃、牛脂、羊脂、牛角、羊角、雞骨架 | 糞便堆成肥料；板油煉成豬油 | 肥料催熟作物；豬油作為廚房炒鍋用油；乳清餵豬；豬鬃做毛刷；氂牛糞曬乾當燃料；牛脂、羊脂加線做蠟燭；羊角換回原版山羊角（樂牧的山羊不會撞落羊角）；牛角、雞骨架磨骨粉，雞骨架也能熬大骨高湯 |

所有產物在 1.0 都要有去處，`npm run validate` 會檢查每個物品都能被吃、使用、放置、燃燒，或被某個配方、加工、料理、飼料消耗。優良、極品雞蛋與三級鵝蛋可以合成原版雞蛋（鵝蛋換 2 顆），這樣廚房裡用雞蛋的料理和原版蛋糕都能用。

品質的處理方式：廚房移植版刻意不含食物品質系統，所以樂牧把三級品質做成三個獨立物品。註冊廚房食譜時，把三級列為同一格的替代材料，任何品質都能做菜；品質差異只體現在樂牧自己的加工品與直接食用的回復量。

生熟肉對應透過 `kaleidoscope_cookery:register_wok_meat` 註冊，讓鴨肉等新肉類能在炒鍋直接煎熟。

### 屠體與屠宰

樂牧動物死亡後不會直接掉出肉與皮，只掉落一具屠體；屠體必須掛上屠宰掛架分切，才能得到各部位的肉與副產物。

- **掉落**：十種動物各有自己的屠體物品。牛、水牛、氂牛、豬、羊、山羊的屠體不可堆疊；雞、鴨、鵝、兔的屠體可堆疊。幼體不掉屠體。
- **屠宰掛架**：木架加鐵鉤的方塊，高兩格。手持屠體對掛架互動，屠體就會倒掛在鉤上，一個掛架一次掛一具。屠體不能在地上或手上分切。
- **刀具**：廚房的菜刀（以及任何帶有廚房菜刀標籤的刀）與原版的劍、斧都能分切，產物相同，每一刀消耗耐久。空手或其他工具無法分切。
- **分切**：對掛著的屠體逐刀分切，每一刀切下一類產物，切完後掛架清空。分切從皮開始，掛架上的外觀分三個階段：
  1. **連皮**：剛掛上時就是那隻動物本身，用牠自己的模型與毛色倒吊，後腿在上。
  2. **去皮**：皮、毛或羽毛那幾刀都切完後，換成去頭、去皮的屠體：畜類是紅肉與油花，豬是粉色豬皮，禽類是拔光毛的皮色並保留腳。
  3. **切半**：切到一半之後只剩後半身，切口露出脂肪、油花與骨頭。
- **先剝皮的刀**：牛、水牛、山羊、豬、兔第一刀取皮；氂牛先剃毛再取皮；未剪毛的羊先得羊毛再取皮；鴨、鵝先取羽絨再取羽毛；雞第一刀取羽毛。外部附加包的分切表可用 `skin: true` 標出這幾刀，沒標時第一刀視為剝皮。
- **產量**：大型動物的屠體會記錄性別，公的分切量較多；好感度不影響肉量。
- **與廚房相容**：分切一定會產出原版的生肉物品，所以廚房既有用生牛肉、生豬肉、生雞肉、生羊肉、生兔肉的食譜全部照常可用。部位肉是額外的樂牧物品，用於樂牧新增的料理。
- **保存**：1.0.0 的屠體不會腐壞，可以先存放再分切。

## 技術架構

樂牧是廚房的「附加包（ADDON）」角色，套件結構與腳本分層完全比照廚房 v1.6.6。

### 套件與版本

- 行為包與資源包各一，打包為單一 `.mcaddon`。
- `min_engine_version` 1.26.1，`@minecraft/server` 2.7.0，`@minecraft/server-ui` 2.0.0，與廚房一致。
- 在 manifest 以 UUID 宣告依賴廚房行為包（最低版本 1.6.6），沒有廚房就無法啟用樂牧。

### 腳本目錄

| 目錄 | 內容 |
| --- | --- |
| `main.js` | 只做啟動：註冊元件、事件與整合 |
| `data/` | 動物定義表、飼料表、加工配方、廚房食譜封包、手冊內容 |
| `custom_components/` | 飼槽、水槽、巢箱與各加工方塊的自訂元件 |
| `events/` | 原版動物轉換、性別與繁殖、每日結算、擠奶、刷毛、菜刀掉落 |
| `api/` | 對廚房、煙火的整合層，以及樂牧自己對外的註冊介面 |
| `utils/` | 無生命週期責任的小工具 |

### 與廚房的整合流程

1. 啟動後送出 `kaleidoscope_cookery:api_ping`。
2. 收到 `kaleidoscope_cookery:api_ready` 後，讀取 `capabilities` 清單。
3. 依能力逐筆送出 `register_recipe`（炒鍋、湯鍋、砧板、蒸籠、茶壺、石磨）與 `register_wok_meat`。
4. 有 `guidebook_extensions` 能力時，註冊手冊章節。
5. 若始終沒收到回應，在聊天欄提示廚房版本過舊或載入順序有誤。

廚房的註冊只存在於當次世界載入，所以每次載入都重新註冊；重複註冊是安全的。

### 對外擴充 API

樂牧會開放一套公開 API，讓其他附加包不改樂牧本體就能加入新動物、飼料與加工配方。做法與廚房相同：以腳本事件（Script Event）傳遞 JSON，不允許直接匯入樂牧的腳本檔。

| 事件 | 方向 | 用途 |
| --- | --- | --- |
| `kaleidoscope_ranching:api_ping` | 外部 → 樂牧 | 詢問樂牧是否就緒 |
| `kaleidoscope_ranching:api_ready` | 樂牧 → 外部 | 回覆 API 版本與能力清單 |
| `kaleidoscope_ranching:register_animal` | 外部 → 樂牧 | 讓外部動物加入性別、好感度、每日需求與產物系統 |
| `kaleidoscope_ranching:register_feed` | 外部 → 樂牧 | 新增飼料或零食，指定等級與適用動物 |
| `kaleidoscope_ranching:register_recipe` | 外部 → 樂牧 | 為攪乳桶、乳酪壓模、熟成架、發酵罐、醃製缸新增配方 |
| `kaleidoscope_ranching:register_butcher` | 外部 → 樂牧 | 為外部動物定義屠宰掛架的分切產物 |
| `kaleidoscope_ranching:animal_event` | 樂牧 → 外部 | 廣播出生、孵化、收成等事件，供任務或成就類附加包使用 |

另外提供不需腳本的標籤契約：

- 物品標籤：`kaleidoscope_ranching:milk`、`kaleidoscope_ranching:fertilized_egg`、`kaleidoscope_ranching:feed`、`kaleidoscope_ranching:brush`，外部物品掛上標籤即被樂牧認得。
- 實體族群：`ranching_livestock`、`ranching_male`、`ranching_female`，外部附加包可用來篩選樂牧動物。

規則比照廚房的 v1 API：

- v1 的事件名稱與欄位保持相容；若要破壞性變更，改用新的 API 版本號。
- 註冊只在當次世界載入有效，移除外部附加包後不留殘餘；重複註冊是安全的。
- 樂牧內建內容優先，外部無法覆蓋；外部只能註冊自己命名空間的物品與實體。
- 隨包附 API 文件、範例腳本與範例封包，格式比照廚房的 `documentation/` 資料夾。

### 光影支援

樂牧會支援基岩版內建的 Vibrant Visuals 光影模式，為方塊、動物與物品提供 PBR 材質。

- 資源包 manifest 宣告 `pbr` 能力。Vibrant Visuals 的 PBR 材質不只用於方塊，也能用於實體、粒子與物品（[微軟官方文件](https://learn.microsoft.com/en-us/minecraft/creator/documents/vibrantvisuals/vvresourcepacks)）。
- 每張貼圖附一組材質檔：顏色、金屬度與自發光與粗糙度（MER）、法線或高度圖。
- 重點效果：金屬奶桶與擠奶架的反光、水槽水面、孵化器熱源的自發光、動物毛皮與羽毛的粗糙質感、乳酪與奶油的潤澤感。
- 玩家沒開光影時只讀顏色貼圖，外觀與效能不受影響。
- 樂牧只提供自己內容的材質，不改全域的光照、天空與霧氣，避免蓋掉玩家自己裝的光影包。

廚房 v1.6.6 的資源包已宣告 `pbr` 能力，但沒有任何材質組檔，所以樂牧在光影下的質感會比廚房的方塊更明顯。材質圖由腳本從顏色貼圖生成再逐項調整，貼圖工作量約增加一倍。

### 美術製作

- **模型**：動物與造型方塊在 Blockbench 製作，模型與貼圖由 `art_src/` 裡的腳本產生，可以重跑；Blockbench 專案檔一併保存。生成流程看到手做的模型就直接採用，不會被程式產生的暫代版本覆蓋。
- **方塊**：乾草架、拴畜樁、屠宰掛架用手做模型；其餘方塊先用程式產生的版本，之後逐一替換。屠宰掛架直接讀取十種動物的模型與貼圖，動物外觀更新時重跑一次即可同步。
- **物品圖示**：以 RetroDiffusion 的 Minecraft 物品風格生成 16×16 圖示，每項出 4 張候選，再人工挑選；品質與受精的版本在同一張圖上加標記。挑不到合適候選的物品改用程式手繪。提示詞與選擇紀錄都存在版本庫，API 金鑰只放在環境變數。

### 可維護性約定

- 動物、飼料、配方全部寫成 `data/` 裡的宣告式表格，新增一種動物只改資料，不改邏輯。
- 物品、方塊、語言檔由同一份定義表生成，避免手改多處造成不一致。
- 隨包附 `ARCHITECTURE.md` 與擴充 API 文件，讓其他開發者或 AI 代理能照文件接手。
- 不覆寫任何原版檔案，不使用全域輪詢；所有狀態存在實體或方塊自身。

### 授權

程式與美術皆為原創，模型、貼圖與動畫先由 Claude 製作，物品圖示以 RetroDiffusion 生成，不複製廚房與原版的資源檔；「與原版造型對齊」只指風格與比例，貼圖全部重畫。廚房的資源採 CC BY-NC-SA 4.0，若日後要改作其貼圖，樂牧的對應資源也必須採相同授權、署名且不得商用。發佈頁需標明「非官方」。

## 風險與對策

最大的風險是「取代原版動物」與「屠體取代直接掉落」兩項改動對既有存檔與其他附加包的影響。

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 取代原版動物影響其他附加包 | 針對這六種原版動物的其他附加包功能，不會作用在樂牧版本 | 樂牧動物沿用原版的族群標籤與掉落物；廚房的菜刀掉落由樂牧自行對應 |
| 投擲雞蛋的攔截 | 原版雞蛋仍可能孵出小雞，繞過受精蛋規則 | 以生成事件移除；M1 先驗證可行性 |
| 美術風格 | Claude 製作的模型與貼圖可能與廚房的畫風不一致 | M0 先交一種動物的樣張供確認，再做其餘；2026-11-16 試過大眼睛的 Q 版造型後，確認改以原版造型為準 |
| 大量動物的結算成本 | 伺服器卡頓 | 延遲結算，每次只處理飼槽範圍內的動物，並設上限 |
| 廚房改版 | 硬性依賴下，廚房更新可能讓樂牧無法載入或食譜失效 | 只用 v1 公開事件，註冊前檢查能力清單；廚房改版後同步發佈相容版 |
| 基岩版改版破壞腳本 | 整包失效 | 鎖定穩定版 API，不用 beta 模組 |
| 屠體取代直接掉落 | 玩家初期沒有屠宰掛架就拿不到肉；自動化農場只會收到屠體 | 屠宰掛架配方只用木材與鐵錠，原版的劍或斧就能分切；手冊第一頁說明屠宰流程 |
