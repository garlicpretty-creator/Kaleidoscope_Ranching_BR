# 樂牧 M2「照顧核心」交接文件

版本 0.2 · 2026-11-15

## 範圍

依企劃書 M2 一節，本包完成以下內容：

- **系統**：好感度（0–5 心）、四項每日需求（飼料、飲水、照料、清潔）、延遲式每日結算。
- **方塊**：飼槽、水槽、自動餵食器、自動飲水器、鍘草機、飼料攪拌桶、鹽磚、堆肥槽、苜蓿作物、糞便。
- **道具**：毛刷、牧場記事本、耳標、糞叉、飼料袋、4 種動物零食。
- **材料**：苜蓿與種子、飼草、混合飼料、精飼料、糞便、肥料、豬鬃。

## 合併進 repo（原始指示）

1. 把 `BP/`、`RP/` 的內容併進樂牧行為包與資源包。
2. 在 M1 的 `scripts/main.js` 加一行：`import "./care_init.js";`
3. 語言檔、`terrain_texture.json`、`item_texture.json`、`blocks.json` 若 M1 已有同名檔，**合併條目**，不要整檔覆蓋。
4. 方塊、物品、配方、語言與貼圖都由 `tools/gen_content.py` 生成。要改名字或數值時改這支腳本再執行，不要手改產出的檔案。

## 與 M1 的契約（`scripts/data/m1_contract.js`）

| M2 假設 | 值 | M1 需要做的事 |
| --- | --- | --- |
| 實體 ID | `kaleidoscope_ranching:cow / sheep / goat / pig / chicken / rabbit` | 若不同，改 `data/species.js` 的鍵 |
| 族群 | `ranching_livestock`、`ranching_male`、`ranching_female` | 實體 JSON 加上這三個族群（企劃書已定） |
| 懷孕 | 動態屬性 `kr:pregnant_until_day`（預產的遊戲日） | 名稱不同就改契約檔 |
| 耳標事件 | `kaleidoscope_ranching:add_ear_tag`（加 `minecraft:persistent`） | 選配；沒有時改用名牌防止消失 |

M2 提供給 M1 與 M3 呼叫的函式（從 `care_init.js` 匯出）：

- `needsMetToday(e)`：M1 的繁殖檢查，判斷雙方當日需求是否都滿足。
- `getAffection(e)` / `setAffection(e, points)`：幼體繼承好感度用，20 點等於 1 心。
- `getHearts(e)`：取得 0–5 心，M1 可據此縮短繁殖冷卻，M3 用來決定產量與品質。
- `feedTierToday(e)`、`lastDayTier(e)`：回傳 1 到 3 的飼料等級，M3 的奶蛋品質用。

## 玩法規則（實作值，可在 `data/care_config.js` 調整）

- 四項需求全部滿足的一天 **+1 心**。結算在隔天進行，所以連續照顧 5 天後的第 6 天早上會到滿心。
- 連續 2 天沒吃到飼料 **−1 心**。受傷 −½ 心，同一隻每分鐘最多扣一次。
- 鹽磚範圍內的動物每天 +¼ 心，鹽磚 7 天後耗盡。零食每天 +½ 心，每種動物只吃自己愛吃的那種。
- 期間沒被載入的遊戲日視為中性，不加分也不扣分。動物不會因為沒人照顧而死亡。
- **飼槽**容量 15 份，一次只放一類飼料，每隻動物每天吃 1 份。乾草類給牛羊兔，穀粒類給家禽，蔬菜類給豬兔，混合飼料與精飼料全部動物都吃。
- **水槽**倒一桶水可以用 3 天。**自動飲水器**只要緊鄰水源方塊就不會缺水。
- **自動餵食器**放在飼槽正上方，再往上接箱子、漏斗或木桶，會自動把飼料補進飼槽。
- **清潔**：每隻動物每天約有一半機率排出一坨糞便。飼槽方圓 8 格內糞便超過 6 坨，清潔需求就不滿足；糞叉一次可清 3×3 的範圍。管理員可以從記事本的名冊頁關掉這項需求，也可以用指令 `/scriptevent kaleidoscope_ranching:config clean_need off` 關閉。
- **照料**：蹲下空手撫摸動物，或用毛刷刷牠。刷豬有機率掉出豬鬃。
- **記事本**：對動物使用會顯示資訊並可命名；朝空中使用會打開耳標名冊。
- **鍘草機**、**飼料攪拌桶**是專用的合成台。手工合成時 3 小麥換 2 飼草，鍘草機則是 1 小麥換 2 飼草。
- **堆肥槽**：放入 4 坨糞便和 1 份小麥，發酵 1 遊戲日後得到 4 份肥料。肥料可以催熟任何有成長狀態的作物，包括廚房的作物。
- 苜蓿種子：破壞草叢有 12.5% 機率掉落。

## 效能

- 不做全域輪詢。飼槽、水槽、鹽磚每 200 刻檢查一次自己 8 格內的動物，每次最多處理 32 隻；自動餵食器每 40 刻執行一次。
- 糞便數量每個飼槽每天只用原生的 `getBlocks` 數一次。
- 動物狀態存在實體的動態屬性。方塊的時間戳記（堆肥開始時間、當日已消耗）存在以座標為鍵的世界動態屬性，打掉方塊時清除。

## 驗收

`tests/sim.mjs`（API 模擬在 `tests/mock/`，執行前複製到 `node_modules/@minecraft`） 用模擬的 API 跑過以下情境，全部通過：

- 8 頭牛連續照顧 5 天 → 全部 5 心（企劃書驗收標準一）。
- 漏斗接自動餵食器，3 天內 8 頭牛每天都吃到飼料，期間不需手動補料（企劃書驗收標準二）。
- 之後 4 天不餵 → 掉 2 心。
- 雞不吃乾草。
- 堆肥流程正確；鹽磚 7 天後消失；記事本表單可以打開。

**實機尚未測試。** 測試包 `KR_M2_test.mcaddon` 開啟了 `TEST_WITH_VANILLA`，讓原版六種動物直接套用照顧系統，不需要 M1 就能進遊戲驗證。測試模式下所有動物都顯示為「母」，記事本裡的種類名稱會顯示原始鍵名。正式合併時這個開關必須是 `false`（repo 版預設就是 false）。

## 待確認與已知限制

- **零食**是 4 種新物品：苜蓿草餅（牛、羊、山羊、水牛、氂牛）、穀物糕（雞、鴨、鵝）、甜菜糖塊（豬）、胡蘿蔔脆片（兔）。
- **鹽磚配方**目前是 2 黏土球加 2 骨粉。若廚房有鹽，可以改用廚房的鹽。
- **堆肥的稻草**接受小麥，也接受 `kaleidoscope_cookery:straw`（如果廚房的 ID 不是這個要再對一下）。
- 貼圖是程式生成的佔位圖，等 M0 樣張定稿後替換。
- **互動事件**：如果 M1 的實體沒有 interact 元件，`playerInteractWithEntity` 可能不會觸發。這種情況下 M2 會改用「使用物品並以視線瞄準動物」作為備援，但蹲下空手撫摸需要 interact 事件才能運作。
- 企劃書裡的錯字：「鋏草機」改為「鍘草機」，「飼料攢拌桶」改為「飼料攪拌桶」。M3 的「攢乳桶」與「釃製缸」應分別是「攪乳桶」與「醃製缸」。
